# 跑批工作流模板（方案规范／证伪 brief／横切判据／拍板卡／门报行）

人读单一载体：跑批的规则正文只在这里维护。注入块里的 `{templates}` 指到本文件的绝对路径，
要写方案或派复核时照抄对应节。改本文件＝改下一回合生效的规则，不必发版重启。

## 方案文档规范

主会话亲写方案文档（本工作区的落点是 `/home/nvse/code/实施方案/`），骨架按四节：

### 零、白话导读
给用户两段：①总批白话三五句——这轮大概做什么、为什么现在不行（说全貌，不展开做法）；②关键取舍的人话版——决策表里影响理解的自决项各配一句人话（例：为什么用 A 不用 B、某个术语是什么意思），用户不用去搜。全文不出现函数名/文件路径/表名。每批（单批也要）开头批白话：该批具体怎么做的——解决逻辑是什么、按什么顺序动哪几块，配上取舍（选了什么、丢了什么、为什么这么选），写成用户读完就能判断「这个做法合不合理」的样子，篇幅按取舍多少来。用户只读白话段也能拍板与质疑，其余各节是给施工与复核的工程细节。

### 一、现状与差距
承重事实两三段：现有结构在哪、为什么不够、缺口是缺保证还是缺零件；每条带 file:line 证据；病根归类——哪几件症状是同一个病的补偿零件，哪几件看着像病其实各管一层。判错结构的方案后段全歪，这里写死。

### 二、方案与落点（按批分组）
先给设计决策表：选项/推荐/理由三列，已拍板的标注拍板来源；表内不再单列「待拍板节」，未决项在表中标「待拍板」。再按批分组：每批一个子节＝批标题＋落点逐文件一行（文件＋改什么，禁无主的「某处/相关模块」）＋该批验收命令（可粘贴执行、预期明确）＋变异要求（改锚点必红、红后复原）。跨文件绑死关系（落 A 必同步 B）逐条点名并注明由哪条机械门校验——互验不成立＝方案未收口。无中间过渡态：依赖零件与本批同攒一批上线时，不留兼容分支不造过渡件，按终态直写。

### 三、风险
真风险与对策：最可能坏在哪、怎么防/怎么退；不可逆操作单列；无则写「无」。

### 定稿自查（四条，逐条过）
1. 白话导读：无代码标识符；总批＋每批各有白话段，批白话含该批关键取舍的人话版；用户不搜术语能懂、能据此质疑方案。
2. 现状与差距：每条给了 file:line 证据；病根归类清楚（同病补偿件归堆、非病灶说明各管哪层）；推不出缺口的「候选差距」已删。
3. 方案与落点：多批按批分组、单批直给；逐文件可执行，缺文件＝方案没做完；每批验收命令粘贴即跑；互验点都点名且落在机械门上；决策表已拍板项有来源；无中间过渡态（依赖零件同批上线则按终态直写）。
4. 风险：不可逆操作单列；对策可执行；无则写「无」。

过目：交用户过目，认可再施工；必要处配改前/改后例子对比（过目对比只进对话，不写进方案文档）。

## 方案证伪 brief（施工前，对象＝方案文档）

形态角色（派发时作为子代理首句）：
> 你是方案证伪者，首问前提攻击：若从零设计这个功能会用什么形态？现方案的偏离是论证过的还是惯性？

抓什么：方案前提不成立/有更短路径/设计级缺陷（施工前）。

派发纪律（本段逐字执行）：
- 不被方案框架捕获：不只查「执行错」；先答前提攻击那一问，再查①这块设计本身对不对（有无更正规机制被绕过）②有无双真相源/职责混杂/契约含糊 ③是否与本批新机制冲突。
- 一轮、至多两路：第二路只做独立重算对照，不叠加更多路。
- findings 附 file:line 或方案段落原文＋可复跑命令（能跑则跑）；只报问题不附方案大段，根治法归主会话。

## 证伪门 brief（提交前，对象＝净 diff）

形态角色（派发时作为子代理首句）：
> 你是独立证伪者：只拿方案文档与净 diff（不读施工汇报），按方案文档自己重跑验收命令与机械门，独立重算后只报问题

抓什么：施工结果与方案文档/净 diff 的偏差（漏改、改坏、证据不实）。

派发纪律（本段逐字执行）：
- 不采信施工者「已通过」的陈述：自己跑方案文档里的验收命令与机械门，贴出命令与实测输出。
- findings 每条附可复跑命令（file:line＋命令原文＋实测输出），没有复跑命令的条目不算证据。
- 只报问题不附方案；无法判断的域标「转派」而不是硬答。
- 一轮为限：本轮报完即收，不追加重派；余留交主会话裁决。
- 施工段标记口径：判的是「哪个施工段」的净 diff，段外发现单列、不混进本段结论。

## 横切判据

本段逐条执行，不看懂的条目按「转派」处理：
- 阈值标定：每个魔法数是否带来源（官方文档/实测/业务规则）？来源站得住吗？
- 断言判别力：新增的守门断言改坏锚点是否必红（变异测试）？判别力不足的断言等于没有。
- 部分失败显式：多产物流程失败时留下的产物是否显式报错，而不是静默半成品？
- 设计四信号：按 AGENTS.md 设计纪律的四个自检信号，任一命中即为设计级 finding。

## 安全专项五问（单载体：鉴权／越权／输入／上传／PII）

形态角色（显式点名时作为子代理首句）：
> 你是安全评审员，只查五条：鉴权（此用户能操作此资源吗）／越权（带别人 id 能拿到吗·IDOR）／输入校验（长度/类型/格式/注入）／上传（类型/大小/路径）／PII 与 token 进日志吗

抓什么：鉴权/越权/输入/上传/日志脱敏（显式点名时加挂）。

装配口径：缺省不进标准形态装配；涉鉴权/上传/输入/通知/大数值的批由主会话显式点名才进 brief。单数载体，五问只此一处定义（templates.md 之外再写一份即加载失败）。
