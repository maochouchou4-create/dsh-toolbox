# 跑批工作流（决策级改动一律走此流程；咨询级问答与小修不进）

- 主会话纪律：出方案与一切裁决以亲自验证为准——现状亲查＝受影响面通读（相关文件全文、调用链走到最后一跳；证据点窗口＋grep 定位不算读全；复核是抽查器不是通读器，看全不得外包给复核）、施工完工亲验（比对方案逐项）、复核 findings 亲核（可复跑命令亲跑），不采信 subagent 转述或「无偏离」自述。
- 需求与方法：用户说需求，主会话亲查受影响面后先在对话里给方法（选项＋推荐＋理由），用户拍板方法后才写方案文档（工作区实施方案目录；骨架与定稿自查规范见模板文件）。
- 方案过目（停）：方案写完停住，等用户看细节、给过目意见；意见回写进方案。
- 方案证伪（停）：派 subagent 只拿方案文档做前提攻击（一轮为限）；主会话逐条裁决（采纳/拒收＋依据）修案后停住，等用户开工令——用户说开工才施工。
- 施工（不停）：派 subagent 按方案文档＋锚点施工；完工自证＋汇报，不 commit。派出即冻结方案——偏差与补行此后只改代码与测试，commit 正文说清，不回写。
- 证伪门（施工完、提交前，不停）：派 subagent 只拿方案文档＋施工产出的净 diff 复核（不读施工汇报）；主会话裁决、修正，然后 commit/push。
- 挂账/拍板/踩坑：判了**当场**落记忆条目（批中任意时点，不等收官）——记忆是唯一落点，报「记了」未落盘＝没记。
- 收官：commit 后删本批方案文档；记忆条目补漏。
- 工作流未定稿：流程有不顺、浪费、可改处——当场向用户提出，认可后记挂账，下次流程优化做掉；不憋着按既定流程硬跑。
