# 工作流（一切工作类活动怎么开展；决策级改动走其中的跑批流程）

活按量级分路：咨询问答与小修不进流程、直接答直接修；其余工作类活动照本纪律开展——动手前看全受影响面，日常活走派发与命令纪律，动了决策级（方案、规则、契约、跨模块结构）就走末节的跑批流程，不跳步。

## 动手前

- 先看全再动手：受影响面通读（相关文件全文、测试镜像、调用方/引用点、数据消费方），改点成完整清单一次成套执行；出方案/任务书就是第一件手——方案地基必须是受影响面全文通读，不得留给复核兜底；确需跑了才知道的面，动手时点明未看面。
- 现值纪律：skill、记忆条目、工作流模板（方案骨架／证伪 brief／定稿自查等）——做相关的事前必重读文件现值，不凭上次印象、压缩摘要或注入残留拼装（印象与摘要会过期，文件才是唯一现值；重读一次的成本远低于拼错返工）。
- 文档动笔必读 writing-for-agents skill：写或改任何 agent 消费的文档（skill／AGENTS·CLAUDE／记忆条目／指针所指文档）前先 load 它——指针措辞、信息层级、完成判据、修剪以它为单源。

## 派发与命令

- 分工形态：方案前的调查与材料阅读主会话亲自做；施工／验证链／直查／多路复核一律派 subagent，修法＋锚点＋验证命令必须主会话给全，不让子代理自己想怎么做。多路＝并行后台逐只派发、完工通知逐只收，可对单只 send_message 追问。workflow 只在用户点名或需多阶段编排时用（编排坑：`parallel()` 只吃零参函数——map 回调里直接调 agent() 即抛 `item 0 is not a function`，须写 `() => agent(...)`）。
- 派 subagent 必点名模型与强度（workflow 的 agent() 同规）：provider/model 一律显式点名，取值＝cordis.patch.yml `subagent-model-selection-settings` allowedModels 现值（省略＝继承父路线且继承不受 allowedModels 拦＝绕开用户指定路线，禁止省略）；reasoning_effort 按活计自点名，档位现查，不写死映射。
- 子代理命令纪律（subagent 与 workflow 的 agent() 内部）：长命令一律前台跑完；起了后台 job 须回合内收完——回合结束＝job 消亡。
- 命令卫生：测试/长命令输出重定向 /tmp 下再看，勿用 grep/tail 管道包裹（吃 exit code）；后台任务停止后清理残留进程；整理/迁移禁止 rm 迁入目标目录（跨设备 mv 不可恢复）。
- 调试与回归：调试看与动＝playwright-cli 交互式（attach 会话＋run-code 现场驱动、现场读结果）；造数＝现成原语单行调用（gui-test db_common/probe_common）；一次性调试脚本（手写壳文件、自造探针 js）不写。跑全量/回归（full_regression、b 系冒烟、e2e 批）前先清场：关掉本会话开的调试会话、杀掉自起临时服务（代理/静态站）、登出调试期间登过的测试账号（同账号在线会抢登录态与布场指派→e2e 假红）；e2e 跑批窗口内保持清场——禁开调试会话、禁改 renderer 源码。

## 提交与交付

- git 全权：项目仓与 agent-data 同步仓皆 Agent 全权——攒够完整批次自行提交、推送（SSH），不请示不等发话。提交规范以 git-commit skill 为准，不另设门槛。

## 跑批工作流（决策级改动一律走此流程）

- 主会话纪律：出方案与一切裁决以亲自验证为准——现状亲查＝受影响面通读（相关文件全文、调用链走到最后一跳；证据点窗口＋grep 定位不算读全；复核是抽查器不是通读器，看全不得外包给复核）、施工完工亲验（比对方案逐项）、复核 findings 亲核（可复跑命令亲跑），不采信 subagent 转述或「无偏离」自述。
- 需求与方法：用户说需求，主会话亲查受影响面后先在对话里给方法（选项＋推荐＋理由）；用户看过方法、攻过前提后说「出方案」，才写方案文档（工作区实施方案目录；骨架与定稿自查规范见模板文件）。
- 方案证伪（不停）：方案写完直接自动派 subagent 只拿方案文档证伪（一轮为限，保底砍刀）；主会话逐条裁决（采纳/拒收＋依据）修案后停住，等用户开工令——用户说开工才施工。
- 施工（不停）：派 subagent 按方案文档＋锚点施工，派前先判续接候选（判据见模板「续接优先」）；施工问询/待决报文到达的回合即受理——当场裁或转问询用户，不静默搁置；完工自证（环境无关门；起服/过网的冒烟段归主会话后台跑）＋汇报并自行 commit（不 push；标题只写主题、细节与偏差下沉正文）。派出即冻结方案——偏差与补行此后只改代码与测试，commit 正文说清，不回写。
- 证伪门（施工提交后、推送前）：复核自动派不停——派 subagent 只拿方案文档＋施工产出的净 diff 复核（不读施工汇报）；主会话亲核 findings、给出修法后**停**，等用户前提攻击或确认再派修复（优先 send_message 回原施工 subagent 续其上下文，不可续接才新派）；修复完工主会话亲验补 commit 后 push；无 findings 的 green 直通 push。
- 挂账/拍板/踩坑：判了**当场**落记忆条目（批中任意时点，不等收官）——记忆是唯一落点，报「记了」未落盘＝没记。
- 收官：commit 后删本批方案文档；记忆条目补漏。
- 工作流未定稿：流程有不顺、浪费、可改处——当场向用户提出，认可后记挂账，下次流程优化做掉；不憋着按既定流程硬跑。
